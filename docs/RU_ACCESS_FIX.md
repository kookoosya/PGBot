# Почему сайт не открывается в России (и как починить)

**Домен:** `pushkinskie-gory.xyz`  
**Симптом:** белый экран, «ошибка», предупреждение браузера/антивируса, сайт «не грузится» — **без VPN**.

---

## Главная причина (2025–2026)

С **9 июня 2025** крупные российские провайдеры (Ростелеком, МТС, Мегафон, Билайн и др.) **дросселируют трафик к Cloudflare**: на соединение отдаётся ~**16 КБ** данных, после чего страница обрывается.

Это **не** блокировка вашего домена в реестре РКН. Домена может не быть в списке — ломается **любой** сайт за **оранжевым облаком** Cloudflare (Proxied).

Официально: [Cloudflare — disruption for Russian users](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/service-disruption/)

**Вывод:** режим **Proxied (оранжевое облако) для РФ сейчас не подходит.**

---

## Решение 1 — быстрое (5 минут): DNS only в Cloudflare

Оставляем Cloudflare только как DNS, **без прокси**. Пользователи идут **напрямую** на VPS `192.210.213.135`.

### В Cloudflare → DNS → Records

| Type | Name | Content | Proxy |
|------|------|---------|-------|
| A | `@` | `192.210.213.135` | **DNS only** (серое облако) |
| A | `www` | `192.210.213.135` | **DNS only** (серое облако) |

1. Кликни по **оранжевому** облаку → станет **серым** («DNS only»).
2. Сохрани обе записи.
3. Подожди 5–15 минут.
4. Проверь с телефона **без VPN** (лучше мобильный интернет):  
   https://pushkinskie-gory.xyz

### SSL в Cloudflare

После переключения на серое облако SSL на стороне Cloudflare **не используется**. Сертификат выдаёт **VPS** (Let's Encrypt) — уже настроен.

В Cloudflare → SSL/TLS можно оставить любой режим — на прямой доступ он не влияет.

---

## Решение 2 — если прямой IP тоже не открывается

На том же VPS `192.210.213.135` может крутиться другой проект; **IP иногда режут отдельно** от домена.

Тогда нужен **отдельный VPS в России** (Timeweb, Selectel, Beget, RuVDS — от ~200–400 ₽/мес):

1. Поднять nginx reverse proxy на RU-VPS.
2. `proxy_pass https://192.210.213.135` или зеркалировать `/opt/pgbot`.
3. A-запись домена (или `pushkinskie-gory.ru`) → IP **российского** сервера.

Это единственный надёжный вариант, если и Cloudflare, и US-IP недоступны.

---

## Решение 3 — домен `.ru` (опционально)

`pushkinskie-gory.ru` удобнее для жителей, но **сам по себе** доступ не чинит.

- A `@` и `www` → IP сервера, который **реально открывается из РФ** (RU-VPS или US-IP, если не режут).
- **Не** включать Cloudflare Proxied для `.ru`, если аудитория в России.

## Чеклист проверки

С телефона **без VPN**:

| URL | Ожидание |
|-----|----------|
| https://pushkinskie-gory.xyz | Главная портала |
| https://pushkinskie-gory.xyz/health | `{"status":"ok",...}` |

Если `/health` открывается, а главная нет — проблема во фронте (кэш, SW). Жёсткое обновление: Ctrl+Shift+R.

---

## Что НЕ поможет

- Оставлять **Proxied** (оранжевое облако) — в РФ по-прежнему ~16 КБ.
- Менять только SSL Full / Strict — при throttling Cloudflare это не спасает.
- Покупать платный Cloudflare — throttling на стороне провайдеров РФ.

---

## Для агента / VPS

После смены на DNS only на VPS ничего менять не обязательно: nginx + Let's Encrypt уже обслуживают домен.

```bash
cd /opt/pgbot && bash scripts/vps-deploy.sh
```

Проверка на сервере:

```bash
curl -sI https://pushkinskie-gory.xyz/health
dig +short pushkinskie-gory.xyz A   # должен быть 192.210.213.135, не 104.21.x
```
